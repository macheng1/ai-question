# 考试并发访问

开卷、保存答案、交卷原先会独占同一条考试记录，不同学员也需要排队。现在按以下顺序持有事务锁：

1. 考试与关联培训：共享锁，允许不同学员并行；管理端修改、结束仍使用排他锁。
2. 考试 + 姓名 + 手机号：个人排他锁，防止重复开卷、重考次数竞争。
3. 当前答卷：排他锁；查询只锁答卷表，避免联表查询再次独占考试记录。

学习入口同样使用共享配置锁，个人学习会话继续依靠已有唯一键保护。开卷和学习入口使用 READ COMMITTED，以便等待同一学员前一事务后读取新状态。答题、交卷原有 READ COMMITTED 保持不变。

## 数据库升级

新后端需要应用 V53__exam_candidate_guards.sql，现有迁移启动流程会应用。新增个人事务锁表 assessment_candidate_guard，第一次操作时自动补齐记录。不会删除、合并或重置已有学员、答卷和成绩；删除考试时锁记录由外键级联删除。

学习和考试的共享锁使用 MySQL 5.7 和 8 均支持的 LOCK IN SHARE MODE。排他锁查询的外层只读取个人答卷或个人阅读记录，关联配置通过只读子查询获取。

## 验证

本地隔离 MySQL 集成测试覆盖：

- 第一名学员事务未提交，另一学员仍可开卷、保存答案。
- 同一学员并发开卷只创建一份答卷，重考不超过配置次数。
- 已交卷后等待中的保存请求被拒绝，已结算分数不被覆盖。
- 管理端结束考试等待正在保存的答案，随后按已提交答案结算。
- 独立培训、关联考试培训的不同学员学习入口可并行。

这只是移除已复现的串行瓶颈，不代表已经通过 1000 人容量验收；实际吞吐仍需服务器压测确认。
