# 培训阅读压测
在能访问后端的 Linux 或 macOS 压测机上运行。需要 Bash、Node.js 20 或更新版本，无 npm 依赖。压测机会发起真实请求，后端使用当前环境配置的数据库、预览服务和对象存储。
当前后端提交 9706e27 的学习和考试接口使用 MySQL 8 的 FOR SHARE 和 FOR UPDATE OF。内网先查询 SELECT VERSION()。只看到迁移版本 V53 不能证明学习接口可用。先做 1 人实测，返回 500 时停止升档并检查后端日志。
## 准备一个环境
在本目录执行下面两行，输入该测试企业的管理员手机号和密码。
```bash
export API=http://内网服务器:18080/api
bash run.sh prepare round1
```
自动创建压测部门和 1,000 个虚构学员，手机号为 19976140001 至 19976141000。既有手机号必须与压测标识、姓名、部门、启用状态一致，否则准备停止。请在测试企业中使用，因为按「全员」配置的其他培训可能也会纳入新增员工。准备阶段使用管理接口持久化数据，管理员凭据不写入文件。PDF 每页要求 3600 秒。生成后输出培训、材料、部门 ID 和学员 CSV。不同环境请分别使用目录或指定 RUN_DIR，以保留各自批次和结果。
## 分档运行
```bash
bash run.sh test 1 30
bash run.sh test 100 300
bash run.sh test 300 300
bash run.sh test 500 300
# 对照测试：500 人在 120 秒内均匀入场，每人学习 300 秒
bash run.sh test 500 300 120
bash run.sh test 1000 1800
```
每次完成后再决定是否升档。每个独立身份间隔约 20 毫秒发起进入流程，进入后读取 PDF 第一页，每 5 秒上报有效时长，每 30 秒再次读取预览。一次测试最多累计每页 3600 秒，重复跑到上限时，执行 prepare round2 创建新培训并复用原学员。请避免同时准备两个同名批次。中途准备失败可用相同批次名重跑；预览失败时先在管理端重试生成。
## 核对
终端及 run-data/result-*.log 给出请求数、各接口 P95、最大延迟和 HTTP 状态。peak 应达到目标人数，finished 和 advanced 均等于目标人数，failed 为 0。advanced 表示服务端最后返回的累计时长大于进入时基线。可在管理端按培训名称查看或导出学习日志，核对人员数及有效时长。服务器用 docker stats 查看 API 和数据库资源。测试只覆盖 PDF 阅读与保存进度；视频并发播放与考试交卷须单独验证。Ctrl+C 停止发新请求，输出已完成统计。
